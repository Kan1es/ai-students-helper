# AI-ассистент по учебным курсам

Микросервис на Python/FastAPI с собственной PostgreSQL. Принимает готовый JSON курса,
находит фрагменты учебного текста и сохраняет диалог с источниками. API и обработчик вопросов
запускаются отдельно. Исходная база учебной платформы во время работы не требуется.

По умолчанию включён **режим поиска без LLM**: ответ содержит найденные выдержки, а не
сгенерированное объяснение. Для учебного диалога предусмотрен адаптер совместимого
Chat Completions API; провайдер и модель настраиваются отдельно.

## Запуск в Docker

Нужен Docker Compose v2.24 или новее.

```sh
cp .env.example .env
docker compose up --build -d
docker compose exec api python -m tools.import_json data/data-science.json --url http://localhost:8000
```

Документация API: http://localhost:8010/docs
Состояние сервиса: http://localhost:8010/health
OpenAPI JSON: http://localhost:8010/openapi.json

База доступна только внутри Docker. API опубликован на `127.0.0.1:8010`.
Данные сохраняются в именованном томе. `docker compose down` останавливает сервис,
сохраняя том. Не добавляйте `-v`, если хотите сохранить диалоги и материалы.

Проверка реального запроса с импортом, ожиданием ответа и чтением истории:

```sh
docker compose exec api python -m tools.smoke --url http://localhost:8000
```

Просмотр ошибок:

```sh
docker compose logs --tail=100 api worker
```

## Первый диалог

Идентификатор курса из приложенного JSON: `cd73ac05-af6f-4b84-9af4-aaf210a96a09`.

```sh
curl -X POST http://localhost:8010/dialogs \
  -H 'Content-Type: application/json' -H 'X-Student-ID: student-1' \
  -d '{"course_id":"cd73ac05-af6f-4b84-9af4-aaf210a96a09"}'
```

Подставьте возвращённый `id` вместо `DIALOG_ID`:

```sh
curl -X POST http://localhost:8010/dialogs/DIALOG_ID/messages \
  -H 'Content-Type: application/json' -H 'X-Student-ID: student-1' \
  -d '{"text":"Как работать с таблицами Pandas?","request_key":"question-001"}'
```

Ответ `202` означает, что вопрос сохранён и поставлен в очередь. Его `id` используется
в `GET /messages/MESSAGE_ID`; передавайте тот же `X-Student-ID`. Статусы:
`queued` → `processing` → `completed` либо `failed` после исчерпания попыток.
Повтор одного `request_key` с тем же текстом возвращает уже созданное сообщение.
Другой текст с тем же ключом возвращает `409`. В одном диалоге одновременно обрабатывается
один вопрос; после завершения можно отправить следующий.

## Локальная разработка

Python 3.12+. SQLite поддерживается для тестов и одиночного локального обработчика;
параллельные обработчики используют PostgreSQL.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install -e '.[dev]'
DATABASE_URL=sqlite:///./assistant.db python -m app.init_db
DATABASE_URL=sqlite:///./assistant.db uvicorn app.main:app --reload --port 8010
```

В другом терминале, из корня проекта:

```sh
source .venv/bin/activate
DATABASE_URL=sqlite:///./assistant.db python -m app.worker
```

Переменная `DATABASE_URL` в Compose задаётся самим Compose и указывает на контейнерную БД.
Значение из `.env.example` предназначено для собственной локальной PostgreSQL вне Docker.

## Подключение LLM

В `.env`:

```dotenv
LLM_MODE=api
LLM_BASE_URL=https://your-provider.example/v1
LLM_API_KEY=your-key
LLM_MODEL=your-model
LLM_TIMEOUT_SECONDS=45
MAX_ATTEMPTS=3
```

Провайдер должен поддерживать `POST /chat/completions`, сообщения system/user и
`response_format={"type":"json_object"}`. Это конкретный контракт адаптера, не универсальная
совместимость со всеми LLM API. После изменения настроек:

```sh
docker compose up -d --force-recreate api worker
```

Промпт находится в `prompts/tutor.txt`; его SHA-256 записывается вместе с ответом.
Он задаёт альтернативные объяснения, отделение примеров ассистента от цитат и помощь
с заданиями через подсказки. Правило помощи с заданиями пока предварительное и требует
согласования с куратором. Модель получает до 8 предыдущих завершённых пар вопрос/ответ,
контекст курса и до 5 фрагментов. История ограничена по размеру; полная история сохраняется.

## Данные и обновления

Пример входа: `data/data-science.json`. JSON Schema: `docs/course.schema.json`.
Сервис проверяет уникальность уроков/блоков, ссылки на блоки, хеши текстов и временные метки.
Идентификаторы курса/уроков сохраняются. Неизвестные дополнительные поля входного JSON
игнорируются; поддерживаемые расширения описаны в схеме.

Импорт — полный снимок курса. При изменениях передайте новую `materials_version`.
Повтор существующей версии с тем же содержимым идемпотентен; другое содержимое под тем
же номером отвергается. Старые фрагменты исключаются из поиска атомарно. Для снятия урока
передайте `active=false` либо исключите его из нового снимка. Для удаления части текста
загрузите новый снимок без неё. Повторный импорт старого снимка возвращает его в активное состояние.
В истории ответов сохраняются снимки использованных источников старой версии.

Тексты режутся на фрагменты до 1600 символов с перекрытием 200 символов. Если есть
`segments: [{"text": "...", "start_ms": 0, "end_ms": 5000}]`, фрагменты сохраняют временной
интервал своего сегмента. Время внутри сегмента не угадывается. `summary` и описание курса
не индексируются как полноценный материал урока. Без текста урок виден в структуре,
но не используется для ответа.

В исходном курсе 20 уроков, 16 с текстом; у всех отсутствуют `source_url`. Поэтому
источники содержат реальные ID, название, текст и `source_file`, но не выдуманные кликабельные
ссылки или таймкоды. `link_status=missing` либо `provided_unchecked`: наличие URL
не означает проверку HTTP-доступности или смыслового подтверждения ответа.

## Выгрузка из PostgreSQL-дампа

```sh
python -m tools.export_dump '/path/to/dump.sql' \
  --course data-science --output data/export.json
python -m tools.import_json data/export.json
```

При известном маршруте платформы добавьте `--lesson-url-template`, например шаблон
с `{course_id}`, `{lesson_id}` или `{slug}`. Маршрут нужно взять у основного проекта.

Инструмент читает COPY text только для `room_room`, `filemanager_lessonblocks`,
`filemanager_file`, исключает `delobj=true`, не исполняет SQL и не переносит таблицы учеников.
Бинарный/сжатый pg_dump сначала преобразуйте в plain SQL через `pg_restore -f`.
Поле `text` переносится как учебный текст, `compressed_text` как дополнительное описание;
инструмент не распознаёт видео и не создаёт отсутствующие транскрипты.
Готовый предоставленный JSON остаётся основным примером и автоматически не перезаписывается.

## Доступ

Первый этап по ТЗ: `AUTH_ENABLED=false`. `X-Student-ID` задаёт тестового ученика
(по умолчанию `demo-student`) и не является подтверждённой авторизацией.
В этом режиме импорт и все курсы доступны без проверки прав; диалоги разделены по этому ID.

Для интеграции предусмотрен переключатель `AUTH_ENABLED=true` и HS256 JWT от основного проекта:
`sub`, `exp`, `iss`, `aud` обязательны, `courses` — список разрешённых ID курсов,
`role=admin` даёт доступ к импорту. Задайте `JWT_SECRET` длиной минимум 32 символа,
`JWT_ISSUER`, `JWT_AUDIENCE`. Клиент передаёт `Authorization: Bearer ...`.
Права проверяются до поиска/чтения; диалоги принадлежат только своему `sub`, включая администраторов.
Выдача JWT и обновление прав остаются на стороне основного проекта. Контракт нужно
согласовать при интеграции; автоматической связи с его пользователями пока нет.

## Проверки

```sh
pytest -q
ruff check app tools tests
python -m tools.evaluate
```

Результаты поиска: `docs/retrieval-results.json`. Сценарии приёмки и границы проверки:
`docs/verification.md`. Автоматическая проверка ссылок выявляет неизвестные ID,
но не доказывает, что объяснение модели подтверждается цитатой; это отдельная оценка куратора.

## Модули

- `app/main.py`, `app/auth.py`, `app/schemas.py` — API, права, контракты.
- `app/materials.py`, `app/search.py` — импорт, версии, фрагменты, BM25 с русским стеммингом.
- `app/llm.py`, `prompts/tutor.txt` — адаптер провайдера и учебная инструкция.
- `app/models.py`, `app/db.py`, `app/worker.py` — хранение и очередь обработки.
- `tools/` — подготовка, импорт, контрольные вопросы и сквозная проверка.

Поиск первого этапа лексический: он учитывает формы русских слов, но не гарантирует нахождение
синонимов. Индекс вычисляется по активным фрагментам выбранного курса в памяти; для большого
каталога его следует заменить/дополнить PostgreSQL FTS или векторным индексом, сохранив контракт.
Схема БД создаётся идемпотентно для версии 0.1.0 через `app.init_db`. Это не механизм изменения
существующих колонок: перед следующим изменением схемы потребуются версионированные миграции.
